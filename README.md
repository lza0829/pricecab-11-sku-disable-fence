# 06-pricecab（价签柜）

Pricecab — 改价单按预约时刻生效，现行价签可查，并与销售夹具对账。

与 Feedstitch（多源归并）、Batchgate（作业编排）、Syncledger（双端对账）、Changecast（CDC 投影）、Proofpack（采样放行）主链路不同。  
不是电商订单/购物车，不是仓库进出库 CRUD，不是考勤 OA。夹具全本地。

## 启动

```bash
docker compose up --build
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5600 |
| API | http://localhost:10600 |

## 主链（0-1）

选商品建改价单（写明生效时刻）→ 拨业务钟或点「应用到期」→ 现行价签更新 → 销售对账看一致/不一致

## 商品启停

「商品启停」页可停用 / 启用商品。停用后该商品不得被写入价签，且策略**全局只贯彻一种**（部署时二选一，改价单建单与应用读同一个值，绝不各按一套）：

| 策略 | 建单 | 应用 |
| --- | --- | --- |
| `reject_on_create`（默认，建单即拒） | 停用商品不得进入新改价明细（整单拒绝，无一行落库） | scheduled 单若含停用商品，**整单拒绝**，价签本不被该单改写；拒绝后即使重新启用也不会再自动生效 |
| `skip_on_apply`（允许建单、应用跳过） | 允许停用商品入单 | 跳过停用行并计数，不写其价签；启用行照常写入；重新启用后须**新的应用周期或新单**才写入该商品 |

```bash
DISABLED_SKU_POLICY=skip_on_apply docker compose up --build
```

并发约束：应用进行中切换启停会被拒绝（409），同一时刻只允许一个应用在跑；应用与启停都不与写入交错，整批要么全成、要么全回滚，不存在按矛盾启停态落半单。销售对账中，停用商品的成交行单独分桶（`disabled_sku`），不计入一致 / 不一致，也不会被默默当作一致。

## 技术栈

Python 3.12 + FastAPI + SQLite；Vue 3 + Vite + Nginx。
